# AI 应用生成工作台

一个纯前端的单文件 Web 工作台：输入需求描述 → AI 生成可直接运行的单文件 HTML 应用 → 实时预览 → 在已生成应用上继续迭代修改 → 一键生成测试用例并导出 Excel。

全部数据保存在浏览器 `localStorage`，无后端、无服务器依赖，构建产物是一个可独立分发的 HTML 文件。

## 一、功能总览

| 模块 | 能力 |
|------|------|
| 生成应用 | 按需求描述调用 AI，产出完整单文件 HTML 应用 |
| 修改应用 | 以当前代码为基准做增量修改，原地更新同一条历史记录 |
| 运行日志 | 生成 / 修改全过程实时日志，含开始、进行中、成功、失败与完成说明 |
| 实时预览 | iframe 沙箱内渲染生成结果，可手动刷新 |
| 代码操作 | 查看源码、一键复制、导出 `.html` 文件 |
| 历史记录 | 自动保存、恢复、删除单条、清空全部 |
| 测试用例 | 基于当前代码生成测试用例，支持复用 / 追加 / 重新生成 |
| 用例浮窗 | 可拖动、可缩放、固定表头、单一滚动区 |
| Excel 导出 | 带表头样式、自动换行、列宽的 `.xlsx` 用例文件 |
| API 配置 | 自定义接口地址、API Key、模型名称 |
| 布局调节 | 左右分栏宽度可拖动，比例持久化 |

## 二、生成应用

1. 在左侧「需求描述」文本框输入你要做的页面或应用，例如：
   - `做一个待办清单，支持添加、完成、删除，带本地保存`
   - `做一个深色风格的个人主页，包含头像、简介和项目卡片`
2. 点击 **生成应用**。
3. AI 返回完整 HTML 后，系统会：
   - 解析并校验代码（自动剥离 markdown 围栏与多余解释文字）；
   - 渲染右侧代码区与实时预览；
   - **新建一条历史记录**并置顶；
   - 在运行日志输出完成说明（代码字符数、耗时、后续建议）。

**输入规则**

- 不能为空；
- 长度不少于 4 个字符；
- 不超过配置的最大字数（输入框下方有实时字数统计）。

## 三、修改应用（迭代）

「修改应用」用于在**已生成的应用**上继续改，而不是重新生成一个新应用。

**使用方式**

1. 确保当前已有生成结果（右侧代码区非空，`修改应用` 按钮可点击）。
2. 把需求描述改成**本次要改动的内容**，例如：
   - `把主色调换成蓝色`
   - `在顶部增加一个搜索框，可按标题过滤列表`
   - `删除底部的版权栏`
3. 点击 **修改应用**。

**执行逻辑**

- 将当前完整 HTML 代码作为修改基准发给模型；
- 要求模型**保留未被要求改动的功能与结构**，只调整相关部分；
- 返回后重新解析代码、刷新代码区与预览；
- **原地更新当前这条历史记录**（更新需求、代码、代码指纹、时间），不会新增一条记录；
- 日志输出改动前后的代码字符数变化、增减量与耗时。

---

## 四、修改应用注意事项

**1. 必须先有应用**
未生成任何应用时，`修改应用` 按钮不可用；强行触发会提示「当前还没有可修改的应用，请先点击生成应用」。

**2. 需求描述不能为空**
点击时若输入框为空，会提示填写本次要修改的内容，并给出示例写法（如「把按钮改成蓝色」「新增一个搜索框」），不会发起请求。

**3. 需求描述未变更会被拦截**
若输入内容与当前记录上一次的需求**完全相同**，说明没有新的修改点，系统会提示「需求描述与上一次完全相同」并终止，避免无意义地重复调用模型、消耗额度。

**4. 需求与当前项目不相关会被提示**
如果修改需求与当前应用完全不沾边（例如当前是待办清单，却要求「把视频播放器改成横屏」），或描述含糊到无法定位要改什么，模型会返回无法修改的说明。此时：
- 弹出提示，说明**为什么无法修改**并给出建议的描述方式；
- **当前代码与预览保持不变**，不会被破坏；
- 日志记录为失败并保留原因。

**5. 修改会使旧测试用例失效**
代码变更后，原有测试用例不再匹配新页面，系统会自动清空该记录的用例（避免编号串号与脏数据）。如需用例，请在修改完成后**重新生成测试用例**。

**6. 超长代码会被截断**
作为修改基准传入的代码有长度上限。应用过于庞大时，建议拆分需求、分多次小步修改，效果更稳定。

**7. 建议小步迭代**
一次只描述 1–3 个改动点，比一次性提十几条需求更容易得到准确结果。

## 五、运行日志

生成与修改过程会在左侧「运行日志」区域实时输出，类似自动化流水线：

| 类型 | 含义 |
|------|------|
| 进行中 | 开始生成 / 开始修改 / 正在调用模型 / 正在解析代码 |
| 信息 | 载入基准代码、预览已更新、历史记录原地更新等过程说明 |
| 成功 | 完成说明：代码字符数、增减量、耗时、后续可做什么 |
| 失败 | 失败原因（空需求、需求未变更、需求不相关、接口报错等） |

其他行为：

- 切换历史记录时，会记录一条切换日志并提示可直接继续迭代；
- 页面加载时若已恢复上次应用，会提示可直接使用「修改应用」；
- 支持**一键清空日志**；
- 清空全部历史时，日志同步清空。

## 六、实时预览

- 右侧大面积预览区，使用 iframe 沙箱渲染生成的 HTML；
- 生成或修改成功后自动刷新；
- 提供 **刷新预览** 按钮，可手动重新渲染（适合带定时器、随机数的页面）；
- 无内容时展示空状态提示。

---

## 七、代码查看 / 复制 / 导出

- **代码区**：展示当前应用的完整 HTML 源码；
- **复制代码**：优先使用剪贴板 API；在非安全上下文等受限环境自动回退到兼容方案；仍失败时会自动选中代码文本并提示手动 `Ctrl/Cmd + C`；
- **导出 HTML**：下载为带时间戳的 `ai-app-YYYY-MM-DD-HH-MM-SS.html`，双击即可在浏览器运行。

---

## 八、历史记录

- 每次**生成**创建一条新记录；每次**修改**原地更新当前记录；
- 列表展示需求摘要、时间、用例数量（无用例时显示「无用例」）；
- **恢复**：点击记录即可还原对应的代码、预览、需求输入与已保存用例；
- **删除单条**：右侧 ✕ 按钮；
- **清空全部**：二次确认后清空，并同步重置代码、预览、需求输入、测试用例、浮窗状态与运行日志；
- 记录数量有上限，超出后自动淘汰最旧的；
- 每条记录带 `codeHash` 代码指纹，用于校验用例与代码是否匹配。

## 九、生成测试用例

1. 先生成或恢复一个应用；
2. 点击右上角 **生成测试用例**；
3. AI 基于**当前应用代码**分析页面功能，产出结构化用例，并在浮窗中以表格展示。

用例策略：

- **复用**：代码未变更时，直接展示已保存用例，不重复调用模型；
- **追加**：在已有用例基础上补充新用例，自动去重并**接着已有编号继续排号**；
- **重新生成**：丢弃旧用例，完全重新生成；
- 代码指纹变化（即应用被修改过）时，旧用例作废，需要重新生成。

页面表格列：用例编号、所属模块 / 功能、用例标题、前置条件、测试步骤、预期结果。

测试步骤与预期结果按序号拆分并**逐条对齐**，便于阅读与执行。

## 十、测试用例浮窗操作

- **可拖动**：按住标题栏拖动，自动限制在可视区域内，不会拖出屏幕；
- **可缩放**：右下角手柄调节大小，带最小宽高限制；
- **位置记忆**：关闭后再次打开保持上次位置与尺寸；
- **固定表头**：纵向滚动时表头保持可见；
- **单一滚动区**：内容再多也只有一个纵向滚动条，不会出现嵌套滚动；
- **自动换行 + 斑马纹**：长文本自动折行，行间区分清晰；
- 支持 `Esc` 关闭。

## 十一、导出 Excel

点击浮窗中的导出按钮，生成 `.xlsx` 文件：

- 在页面六列基础上，额外导出 **实际结果**、**执行人**、**执行日期** 三列，可直接作为执行记录表；
- 表头带样式（底色、加粗、居中）；
- 单元格自动换行，多步骤内容完整可见；
- 预设列宽，无需手动调整；
- 基于 `xlsx-js-style` 实现。

## 十二、API 配置

点击右上角设置按钮，可配置：

| 配置项 | 说明 |
|--------|------|
| 接口地址 | OpenAI 兼容的 Base URL，必须以 `http://` 或 `https://` 开头 |
| API Key | 调用密钥，仅保存在本地浏览器 |
| 模型名称 | 使用的模型标识，留空则用默认值 |

配置保存在 `localStorage`，不会上传到任何第三方服务。留空项会回落到默认配置。

## 十三、界面与布局

- 深色主题，卡片化布局，层级清晰；

## 十四、数据存储说明

全部数据仅存在当前浏览器：

| 内容 | 存储位置 |
|------|----------|
| 历史记录（需求、代码、代码指纹、测试用例） | `localStorage` |
| API 配置（地址、Key、模型） | `localStorage` |
| 分栏宽度比例、浮窗位置与尺寸 | `localStorage` |

注意：

- 换浏览器、换设备、清理浏览器数据都会导致记录丢失；
- 重要成果请及时使用 **导出 HTML** 和 **导出 Excel** 落盘保存。

## 十五、开发与构建

技术栈：原生 HTML + JavaScript + Tailwind 风格样式，Vite 构建，`xlsx-js-style` 处理 Excel 导出。

```bash
# 安装依赖
pnpm install

# 本地开发
pnpm run dev

# 生产构建（产物：dist/index.html）
pnpm run build
```

构建结果是**单个 HTML 文件**，可直接部署到任意静态托管，或本地双击打开使用。

## 十六、常见问题

**Q：点击生成没反应 / 报接口错误？**
检查设置中的接口地址、API Key 与模型名称是否正确，地址需以 `http(s)://` 开头；具体错误信息会显示在提示条与运行日志中。

**Q：修改应用后功能被改坏了？**
建议小步迭代，一次只提少量改动点；历史记录中如有更早的可用版本，可恢复后重新修改。重要版本请先导出 HTML 备份。

**Q：为什么修改后测试用例没了？**
代码变更会让旧用例失效，系统自动清空以避免编号串号，重新点击「生成测试用例」即可。

**Q：提示需求与项目不相关怎么办？**
说明描述无法对应到当前页面的元素或功能，请改用更贴近当前应用的说法，明确指出**改哪个位置、改成什么样**。

**Q：复制代码失败？**
部分浏览器在非 HTTPS 环境禁用剪贴板 API，系统会自动选中代码文本，按 `Ctrl/Cmd + C` 即可。
